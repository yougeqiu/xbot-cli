# feat(activity): connect library creation, installation and metadata lifecycle

Users can create a real activity, recover finish-create by UUID, create a consumer, install/upgrade a published dependency and maintain closed-workspace metadata through the existing inproc bridge. Bridge failures never fall back to official write APIs. Existing app sync/publish commands remain the equivalent lifecycle entry points; metadata writes back up their own originals.

The installation bug was an early memory-dependency check after the download Task: it could fail before dependency callbacks and skip saving. Upgrades additionally require the native document-change notification; Save alone can retain an old dependency pin. The legacy reference tree is already 0.4.2 and the first-batch payload already contains that correction. This change exposes the corrected path and extracts a tested notification/save/wait step: VerifyInstalled → NotifyActivityAdd → RaiseWorkspaceChanged → Save → Python task completion → ContextIdle Save → memory/disk/installed-version checks. It never reloads the workspace or directly patches dependency pins.

CLI contracts cover successful creation/recovery/consumer/install/upgrade/metadata operations, hard failure when offline, dangerous input rejection, busy/wrong targets, stale installation results and nonretryable lost write responses. An isolated PowerShell/C# regression exercises installation completion ordering, engine guards, metadata validation, immutable identity, backups and byte readback. Payload artifacts are rebuilt from the managed sources for embedding.

Validation passed: `cargo fmt --check`; `cargo clippy --locked --all-targets -- -D warnings`; `cargo test --locked` (190 passed, 2 existing ignored, including 35 CLI contracts and the isolated managed regression); Node launcher tests (36 passed); skill tests (16 passed); `npm run test:package` (static release build, package contents and offline installation). The final executable also passed activity help, embedded guide and offline preview smoke checks. Runtime acceptance is pending; use the checklist in `docs/activity-lifecycle.md` on an isolated real client before release. No legacy repository files or client-api catalog entries are changed.
